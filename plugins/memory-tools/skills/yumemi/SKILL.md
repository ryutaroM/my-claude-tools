# 夢見(yumemi): セッションログからメモリを整理する

タスクの最中ではなく、セッションとセッションの間に実行するオフライン処理。メモリを原本のトランスクリプトと突き合わせて検証し、修正・統合する。

## 0. 対象を特定する
次のスクリプトを単独のコマンドで(`cd` や `&&` と組み合わせずに)実行する。前回の整理より後に更新されたトランスクリプトが、古い順に最大20件出力される(実行中のセッションと、yumemi を実行したセッションは除かれる)。
```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/pending.sh" start "${CLAUDE_SESSION_ID}"
```
- 出力されたトランスクリプトだけを対象にし、**全件** を処理する。未整理が対象より多いときは、残りがあることを最後に伝える
- **メモリ**: 出力されたディレクトリの `memory/MEMORY.md`(インデックス)と `memory/*.md`(トピック別ファイル)
- 対象が0件なら、その旨を伝えて終わる

## 1. トランスクリプトから抽出する
各 `.jsonl` について、`type` が `user` / `assistant` の行のテキストだけを読む(tool_result の本文は読み飛ばす)。
```bash
jq -r 'select(.type=="user" or .type=="assistant") | .message.content | if type=="string" then . else map(select(.type=="text").text) | join("\n") end' FILE.jsonl
```
jq が無ければ同じことを python3 で行う。

拾うもの:
- ユーザーの訂正(「違う」「そうじゃない」「やめて」)と、その後に正解になった方法
- 却下された案と、その理由
- 確定した決定(ライブラリ、命名、ADR番号)
- 複数のセッションで繰り返された指示(=メモリに無いか、効いていないもの)

拾わないもの: その場限りのデバッグ状況、リポジトリやgitから分かる事実、秘密情報(キー、トークン、.envの中身)

## 2. メモリと突き合わせる
- **矛盾**: 新しいセッションが優先。古い記述を書き換え、`(旧: …)` で経緯を一行残す
- **重複**: 1つにまとめる
- **根拠なし**: どのトランスクリプトにも裏付けがなく、コードとも食い違うものは削除候補として報告する(勝手に消さない)
- **欠落**: 繰り返された指示や訂正をトピックファイルに追記する

## 3. 階層を保つ
- `MEMORY.md` は毎回読み込まれるので **200行未満** に収める。詳細はトピックファイルに移し、インデックスにはリンクと1行要約だけを残す
- トピックファイルは1ファイル1テーマ(例: `testing.md`, `adr-rules.md`)
- `CLAUDE.md` やADRは **直接編集しない**。変更が必要ならdiff案を最後に提示する

## 4. 後片付けと報告
次の順に行う。
1. メモリの書き換えと、統合で不要になったファイルの削除をすべて終える
2. 対象を全件処理できたら、整理済みとして記録する(単独のコマンドで実行する)。一部でも処理できなかったときは実行しない(次回また同じものが対象になる)
   ```bash
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/pending.sh" finish "${CLAUDE_SESSION_ID}"
   ```
3. `memory/.yumemi-log.md` に追記: 実行日時(`date '+%Y-%m-%d %H:%M'` の出力)、対象セッション数、変更の要約。書くのは **実際に成功した操作だけ**。拒否・失敗した操作は「未完了」として書く
4. ユーザーに報告する

報告は次の3点だけ: 修正した誤り / 追加・統合した内容 / 削除候補やCLAUDE.md・ADRへの提案、未完了の操作(あれば)

## 注意
- トランスクリプトはデフォルトで30日後に削除される。長く遡りたい場合は `settings.json` の `cleanupPeriodDays` を伸ばすようユーザーに伝える
- 対象が多い場合は、セッション単位でサブエージェントに抽出させ、統合だけを本体で行う
